# 4.8.0 Agentic Workflow: Render Stamats and VIDA

Release: `4.8.0`

Runtime state:
`tmp/agentic-workflows/v4-8-0-render-stamats-vida/tracker.json`

## Objective

Render Stamats Communications and VIDA Diagnostics as visible older
professional experience in generated resumes so the resume timeline better
supports the 10+ years summary claim.

## Operating Rules

- Follow root `AGENTS.md` before editing, validating, committing, pushing, or
  closing out release work.
- Use the runtime tracker as the local cursor and evidence log.
- Treat P steps as implementation phases and G steps as reassessment gates.
- Do not mutate `output/tracking/applications.sqlite3`, live tracker rows, or
  stored generated resume artifacts during this workflow unless the user
  explicitly approves that mutation.
- Generate comparison artifacts only under `tmp/`.
- Keep Stamats and VIDA on the same bullet quantity policy as the existing
  rendered non-Oracle roles unless a gate proves that layout or page-count
  quality requires a pause and user approval.

## Plan

### P01 - Readiness Check

Confirm branch, clean worktree, current release metadata, current MRO render
settings for University of Iowa, Steindler, Stamats, and VIDA, and v1
timeout/retry coverage.

### G01 - Scope Reassessment

Confirm whether the plan can proceed using the existing rendered non-Oracle
workflow. Continue only if Stamats and VIDA can inherit the same path as
University of Iowa and Steindler without changing live tracker artifacts.

### P02 - Release and Workflow Metadata

Add this committed plan, bump `pyproject.toml` to `4.8.0`, update the top
`CHANGELOG.md` entry, and add `docs/release-notes/4.8.0.md`.

### G02 - Metadata Reassessment

Confirm release files are aligned and the runtime tracker has evidence for the
committed plan before changing resume behavior.

### P03 - MRO Render Settings

Enable Stamats Communications and VIDA Diagnostics as rendered non-Oracle roles
in `profile/MASTER-RESUME.yml`. Match the existing University of Iowa and
Steindler policy: `min_bullet_points: 2`, `max_bullet_points: 5`, job-level
`render: true`, and source bullet `render: false` until the v1 rewrite produces
job-aware bullets.

### G03 - Resume Scope Reassessment

Pause if parity with the existing non-Oracle bullet policy appears likely to
break the intended three-page strategy, create cramped layout, or require
summary wording beyond a small factual refinement.

### P04 - Regression Coverage

Add focused tests for MRO role inclusion, render settings, and v1 timeout/retry
coverage across all rendered non-Oracle jobs.

### G04 - Test Reassessment

Confirm focused tests cover the release behavior without overfitting to
generated wording.

### P05 - Tmp-Only Artifact Validation

Generate comparison artifacts under `tmp/` only. Check rendered role inclusion,
page count, and layout quality. Pause before live tracker or stored artifact
mutation.

### G05 - Layout and Quality Reassessment

Continue only if tmp artifacts preserve the intended three-page strategy and do
not look cramped. Pause before changing bullet quantity policy.

### P06 - Full Validation and Commit

Run `git diff --check`, focused pytest, `make lint`, and `make test`. Commit the
scoped release branch if validation passes.

### G06 - Closeout Reassessment

Record final validation evidence and pause before PR merge or release tag
closeout unless the user explicitly approves those steps.

## Pause Conditions

- The workflow would mutate `output/tracking/applications.sqlite3` or live
  generated resume artifacts.
- The role policy would deviate from the existing rendered non-Oracle
  `2..5` bullet range.
- The resume exceeds the intended three-page strategy or looks cramped.
- Supporting the 10+ years summary claim requires wording changes beyond a
  small factual refinement.
- Validation failure requires a broader refactor than this release authorizes.
- PR merge or release tag closeout is next.
