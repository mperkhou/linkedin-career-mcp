# 4.6.0 Release Notes: Retryable Partial Batch Workflows

Version 4.6.0 makes tracker batch resume workflows more resilient when one job
row or one timeout-prone LLM/Codex call fails.

## Why This Release Exists

Batch add workflows can now start v1, v2, manual pass, and highlighting for
multiple jobs at once. Before this release, one row-level failure in the first
stage caused the Flask background action to stop the entire chain, even when
other rows had successfully generated drafts and could have continued.

## What Changed

- Added default retry counts for timeout-prone workflow calls:
  - `FIRST_DRAFT_LLM_RETRIES` for v1 LLM steps
  - `SECOND_PASS_RETRIES` for v2 critique calls
  - `CODEX_RETRIES` for manual pass and highlighting Codex calls
- Added CLI flags for those retry counts so local runs and Makefile workflows
  use the same defaults.
- Changed tracker background actions to execute chained workflow stages per job
  and carry only successful job IDs into the next stage.
- Let partial-success batches finish as completed actions with clear failure
  messages, while all-failed batches still fail the background action.
- Preserved existing single-job behavior and target ordering.
