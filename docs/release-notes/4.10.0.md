# 4.10.0 - Split agentic workflow bootstrap and execution

Version 4.10.0 separates workflow initialization from workflow execution.
`agentic-workflow-init` now owns the bootstrap phase: create the branch, confirm
the target version, create the committed canonical plan, add the bootstrap
changelog entry, commit those bootstrap artifacts, initialize ignored runtime
state, bind that state to the committed plan digest, and produce the kickoff
prompt for a fresh controller session.

`agentic-workflow-controller` now focuses on executing or resuming existing
plans. Runtime tracker state is a cursor and evidence log, not a second plan.
G-gate amendments update the committed plan, add a same-version changelog
bullet, commit those changes, and rebind the tracker digest/revision.

The runtime helper now records attempted steps separately from completed steps,
prevents completed step IDs from being silently changed, writes tracker JSON
atomically under a lock file, validates plan digest bindings, rejects
secret-like keys and values, confines repo-local paths, records sanitized
artifact manifests, and preserves evidence-route lifecycle compatibility.

Validation notes:

- Run quick validation for both `agentic-workflow-init` and
  `agentic-workflow-controller` after skill edits.
- Runtime state remains ignored under `tmp/agentic-workflows/<workflow_id>/`.
- Heavy or sensitive evidence belongs under
  `$TMPDIR/linkedin-career-mcp-agentic/<workflow_id>/<step-id>/<run-id>/`.
- This release does not mutate tracker DB rows, generated resumes, or live
  application artifacts.
