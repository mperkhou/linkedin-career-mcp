# 4.4.0 Release Notes: Release-Note Guardrails

Version 4.4.0 makes release notes a first-class part of release hygiene.

## Why This Release Exists

The repo already required aligned package metadata, changelog entries, merged
PRs, and pushed release tags. Release notes were still easy to forget, even
though they are the most useful place for future agents and operators to
understand why a release exists.

## What Changed

- Updated `AGENTS.md` so every committed PR/version bump must update the
  matching `docs/release-notes/<version>.md` file.
- Mirrored the release-note requirement in the command-level
  `linkedin-career-mcp` skill and README release closeout section.
- Backfilled release-note files for all changelog versions greater than
  `3.0.0` that were missing standalone notes.
- Added tests that require every changelog version after `3.0.0` to have a
  matching release-note file.
- Added a named CI step that runs the release metadata and agent-guidance tests
  before the full test suite.
- Bumped the package version to `4.4.0`.

## Validation

Validate with:

- `git diff --check`
- `.venv/bin/python -m pytest tests/test_release_metadata.py tests/test_agent_guidance.py`
- `make lint`
- `make test`
