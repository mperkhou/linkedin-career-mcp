# 4.2.1 Release Notes: Second-Pass Bullet Reorder Alias

Version 4.2.1 makes v2 refinement more tolerant of a recoverable model schema
near miss and fixes an Actions-menu chaining case.

## Why This Release Exists

One v2 batch failed when the model returned `reorder_bullets` instead of the
allowed enum value. The workflow should normalize that near miss rather than
failing an otherwise usable batch. The tracker also needed to allow highlighting
after a standalone manual pass variant workflow.

## What Changed

- Normalized `reorder_bullets` to a tolerated second-pass critique change type.
- Added regression coverage for the alias.
- Allowed the tracker Actions menu to chain Codex highlighting after the manual
  pass variant workflow, targeting the stored `manual` variant.
- Bumped the package version to `4.2.1`.

## Validation

This note was backfilled in 4.4.0 from the changelog entry so release-note
coverage is complete for post-3.0.0 releases.
