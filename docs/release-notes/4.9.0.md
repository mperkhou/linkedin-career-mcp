# 4.9.0 - Evidence-Route Workflow Orchestration

Version 4.9.0 extends the `agentic-workflow-controller` skill with read-only
evidence routes. A workflow step can now split investigation into named routes
that run through subagents when available, or through a local fallback prompt
when not. The main agent remains responsible for edits, gate decisions, tracker
updates, commits, PRs, and release closeout.

The release adds route lifecycle commands to the workflow-state helper, updates
the tracker schema/template with optional `evidence_routes`, and stores detailed
route output under ignored runtime state in `tmp/agentic-workflows/<workflow_id>/`.

The README and ADR 0006 explain the orchestration layer: it reduces repetitive
prompt/response management, makes evidence collection more consistent, and keeps
automation guided by explicit P-step and G-gate boundaries.

Validation should include focused controller tests plus normal release checks.
