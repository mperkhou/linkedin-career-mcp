# 4.11.0 - Strengthen shared platform resume evidence

Version 4.11.0 strengthens the canonical master-resume evidence so future
resume generations can accurately distinguish PDAF's team-owned shared-platform
scope from Max's individual implementation contributions. It also makes
governed agentic delivery explicit without attaching shared-platform scale to
observability work.

Resume evidence changes:

- Reframe the professional summary around Senior Platform Software Engineering,
  team-owned shared automation platforms supporting more than 40,000
  non-network systems, and governed agentic workflows as an engineering
  delivery layer.
- Add a concise Oracle role overview that separates PDAF's ownership of shared
  OLAM and Chef/ORC platforms from Max's implementation, operational hardening,
  reusable workflow, and enablement contributions.
- Strengthen and consolidate the Oracle evidence for OLAM operations, Chef
  policy maintenance, governed delivery, documentation and training, ONDA
  program scope, Max's ONDA implementation work, federated platform
  stewardship, and agentic delivery.
- Preserve separate metric narratives: OLAM supports more than 40,000
  non-network systems, mostly OCI instances; Chef/ORC spans well over 40,000
  servers, with 40,000 representing its pre-Cerner scale; and ONDA separately
  spans more than 12,000 network devices. OLAM and Chef populations may overlap
  and their counts are not additive.
- Separate `Shared Platform Stewardship and Federated Enablement` from
  `Governed Agentic Delivery` as distinct Oracle source-evidence categories.
- Document the federated operating model: PDAF owns the shared OLAM clusters,
  playbooks, frameworks, operations, guardrails, Chef-server estate, policy
  lifecycle, publishing mechanisms, selected base cookbooks, training, and
  guidance. Downstream engineering and SRE teams generally own domain-specific
  playbooks and cookbooks, peer-review cookbook changes, and submit merged Chef
  changes through the PDAF-managed Oracle APEX publishing application.
- Add the grounded optional skills `platform governance`, `self-service
  automation platforms`, and `configuration management at scale`; rebuild the
  affected evidence linkages; restore the evidence-backed `continuous
  integration` link; and remove attribution-sensitive links from paragraphs
  where only PDAF or downstream-team context supported them.

Migration and regeneration notes:

- No schema or tracker migration is required.
- Future resume generations consume the new evidence from the canonical MRO in
  `profile/MASTER-RESUME.yml`.
- Existing DB-backed `v1`, `v2`, and `manual` variants remain unchanged until
  explicitly regenerated.
- `make regenerate-aro-objects` preserves each existing ARO's
  `professional_experience`, so it is insufficient for a full backport of the
  revised Oracle evidence.
- A full existing-job refresh requires
  `make regenerate-resumes JOB_IDS=<id> FIRST_DRAFT_FORCE=1`. Run
  `make manual-pass-resumes JOB_IDS=<id>` afterward only when an updated
  `manual` variant is desired.
