# 3.0.0 Release Notes: JOD-Target ARO Resume Generation

Version 3.0.0 changes the default resume-generation architecture from local
bullet scoring and selection to JOD-targeted generative rewriting.

The short version: let generative LLMs generate, not pick.

## Why This Release Exists

The prior ARO workflow selected existing master-resume bullets by scoring each
candidate against the job opening. That seemed safer because it limited output to
known source text. In practice, the selector optimized proxy signals while the
final resumes got weaker: more selected bullets looked relevant to the selector,
but ATS scores, missing-term behavior, and qualitative fit often moved in the
wrong direction.

The v3.0.0 workflow keeps the evidence discipline but moves the creative work to
the LLM:

- The MRO remains the canonical source of truth.
- Each job gets a deep-copied ARO.
- The JOD is distilled into compact requirement targets.
- Experience bullets are rewritten from source evidence for each role.
- Current-role paragraph evidence is stored in the master resume and consumed
  through the ARO, so generation does not need `tmp/master-paragraphs.md`.

## What Changed

- The production draft workflow now generates rendered experience bullets from
  JOD targets and ARO source evidence.
- Current-role paragraph evidence was promoted into
  `profile/MP-MASTER-RESUME.txt` and `profile/MASTER-RESUME.yml`.
- Legacy experience-bullet scoring and score-bucket selection were removed from
  production draft generation and ARO regeneration.
- Core Technical Skills matching remains, but only for the rendered skills
  section. It now uses the same GLM 5.2 default path as JOD target creation and
  bullet rewriting.
- The Flask tracker regeneration action, Makefile commands, and CLI paths now
  run the v3.0.0 workflow.
- README diagrams and examples were updated around the JOD-target flow.
- Package versioning moved to `3.0.0` because this is a breaking workflow change.

## Experiment Lineage

The decision came from two rounds of experiments.

First, the earlier `~/dev/codex/linkedin-career-mcp-experiment` branch
`codex/aro-ranking-experiment-v2` tested progressively more complex local
selection systems:

- Selector V2 used deterministic candidate extraction, explainable scoring, JOD
  requirement coverage, skill diversity, ATS aliases, and coverage penalties.
- Refreshed-MRO Selector V2 made the selected bullets look more aligned to
  DevOps source evidence, but overall ATS dropped from 77.8 to 74.0 across eight
  jobs, with seven negative job-level deltas and 14 added missing terms.
- Selector V3 added embedding similarity, exact-term preservation, caps, and
  threshold tuning. The tuned run was still down 4.8 points against old Selector
  V2 and down 1.0 point against refreshed-MRO Selector V2.

That work is documented from session `019ec7db-63c5-7771-8763-3dfff10fcca4` and
cache reports under:

- `~/dev/codex/linkedin-career-mcp-experiment/output/experiments/selector_v2_mro_comparison/selector_v2_mro_compare_20260615T235710Z/`
- `~/dev/codex/linkedin-career-mcp-experiment/output/experiments/selector_v3_embeddings/selector_v3_embeddings_tuned_20260616T021244Z/`

Second, this repo tested JOD-target generation and current-role paragraph
rewriting against `url-9823c4455364`:

| Variant | Tokens | Cost | Result |
| --- | ---: | ---: | --- |
| Existing selected bullets plus JOD targets | 5,414 | $0.0146776 | Good, but constrained by preselected bullet inventory. |
| All current-role evidence paragraphs plus JOD targets | 7,995 | $0.0198840 | Best quality and strongest factual grounding. Adopted. |
| Split target-category routing plus selected paragraphs | 5,358 | $0.0104022 | Cheaper, but lost specificity and quality. Rejected. |
| Enhanced split using rebuilt master-resume evidence, skills, and categories | 17,597 | $0.0339568 | Better grounded than plain split, but cost more and still filtered out key evidence. Rejected. |

The same pattern repeated: adding more selection logic made the system look more
controlled, but the final resume got weaker than direct, evidence-grounded
generation.

## Decision

The v3.0.0 default is Method 2:

1. Keep JOD parsing and trimming.
2. Build a JOD object with compact requirement targets.
3. Initialize the ARO from the MRO.
4. Match Core Technical Skills for the rendered skills section.
5. Rewrite rendered experience jobs from ARO evidence and JOD targets.
6. Store the ARO, rendered HTML/PDF, and ATS values in SQLite.

The workflow still has guardrails:

- Use only evidence present in the MRO/ARO.
- Preserve exact metrics from source evidence.
- Ignore unsupported JOD targets instead of inventing coverage.
- Keep manual review and edit loops in the Flask tracker.

## Migration Notes

- Regenerate AROs after upgrading to 3.0.0 so stored resume objects use the new
  paragraph-evidence workflow.
- `tmp/master-paragraphs.md` is no longer a runtime dependency.
- Existing cached experiment artifacts are useful for comparison, but they are
  not required for normal operation.
- The old scoring and selection code should not be treated as a fallback unless
  a future experiment explicitly revives it behind a new opt-in path.
