# 4.7.0 Release Notes: Agentic Workflow Controller Skill

Version 4.7.0 adds a reusable procedural controller for larger staged
implementation work. It does not change resume generation, tracker database
schema, or application artifacts.

## Why

Some repository changes now span multiple implementation steps, reassessment
gates, validation passes, and release-closeout actions. Keeping that work as a
single freeform prompt makes it harder to resume safely, preserve scope, and
decide when user input is required. The controller pattern gives Codex a small,
repeatable way to track progress while leaving product behavior unchanged.

## What Changed

- Added `skills/agentic-workflow-controller/SKILL.md` for staged P/G workflows.
- Added tracked workflow tracker, schema, and plan templates under the skill's
  `assets/` directory.
- Added `scripts/workflow_state.py` to initialize and update ignored runtime
  workflow state under `tmp/agentic-workflows/<workflow_id>/`.
- Documented the controller in the README and architecture docs as procedural
  Codex guidance, not a background daemon or permission bypass.
- Added regression coverage for the skill contract, template validity, runtime
  initialization, validation, and overwrite protection.

## Operational Notes

Runtime state belongs under ignored `tmp/agentic-workflows/`. Commit only the
stable templates, skill instructions, helper script, and any finalized plan docs
that are intentionally part of a release.

The controller still follows root `AGENTS.md`: release notes, validation,
artifact safety, tracker database caution, and remote tag closeout remain
mandatory for committed release work.
