# 4.13.0 - Add supervised feature workflow

Version 4.13.0 makes `agentic-feature-workflow` the active approach for new
multi-phase repository work. It provides one supervisor-owned living Markdown
plan, one bounded implementor P phase at a time, and an independent supervisor
G gate after each phase.

## Why This Release Exists

The repository needed a portable, reviewable way to supervise multi-phase
feature work without making a runtime tracker, plan digest, or workflow engine
the active source of authority. The new workflow keeps planning, task
selection, exact approval, gate decisions, corrections, and release closeout
with the supervisor while the implementor owns only its assigned bounded phase.

## Architecture And Operator Implications

Every P/G cycle explicitly selects one supervision mode:

- **Observation only** permits bounded read-only observation and no implementor
  message.
- **Approval-gated attention** requires a verified destination, exact message
  preview, and fresh approval for every message.
- **Bounded contract restoration** permits at most one message across the
  cycle only when observable, material, time-sensitive evidence directly and
  unambiguously restores an existing approved contract. It cannot broaden
  scope, grant permission, change requirements, or become general autonomous
  authority.

Operators retain exact approval boundaries for task creation, ordinary
messaging, corrections outside that bounded envelope, and release closeout. The
workflow records its decisions in one living Markdown plan; it does not add a
tracker, JSON state, scheduler, daemon, or automated messaging system.

## Compatibility And Exclusions

`agentic-workflow-init` and `agentic-workflow-controller` remain available for
explicit compatibility work with historical machine-tracked workflows. They are
no longer the default for new multi-phase features. ADR 0008 and the active
documentation describe the replacement architecture, while the revised tracked
5.0.0 and 5.1.0 planning records retain their migration, cutover, rollback,
soak, and acceptance requirements under the one-P/one-G cadence.

This release does not alter the Flask application tracker, tracker database,
application rows, resume variants, profile files, generated artifacts, model
settings, retries, timeouts, or application workflows.

## Validation

The release candidate is validated with the Skill Creator validator; focused
feature-workflow, legacy-controller, Makefile, agent-guidance, and
release-metadata tests; `git diff --check`; `make lint`; and `make test`.
